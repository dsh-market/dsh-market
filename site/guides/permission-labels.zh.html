插件页上的权限标签是什么意思

插件页会列出这个插件的代码看起来能做什么：读文件、联网、运行命令。这一页用大白话解释每个标签，以及这种扫描能告诉你什么、不能告诉你什么。

标签是怎么来的

目录对每个插件发布出来的代码做静态扫描：只读代码，找有没有访问文件、网络、命令行之类的调用，不会真的运行它。所以标签的意思是「代码里有这样的调用」，不是「这个插件会对你这样做」。

「没有扫描到」不等于安全。静态扫描看不到运行时才拼出来的代码、之后才下载的代码，也看不到它没跟进去的依赖里的代码。标签用来告诉你该看哪里，不是结论。

各个标签

标签对你意味着什么
会读取本机文件它能打开你这个账号能打开的文件。处理项目或设置的插件都会这样，很正常。
会写入本机文件它能新建或修改文件。保存笔记、缓存、配置的插件都会这样。
会读你的环境变量它能看到你终端里设置的变量，比如代理设置或 API 密钥。
会联网它能连接其他电脑。调用 AI 模型、检查更新的插件都会联网。
会用你的密钥它会读取 API 密钥或令牌。替你调用模型的插件本来就需要。
能运行命令它能通过命令行启动其他程序。能力很强，开发类工具里很常见。
会调用 AI 模型它会把文字发给模型，这些文字会离开你的电脑，到模型所在的地方。
会自己开任务干活它能启动子智能体，不用你一步步确认。
会在运行时执行拼出来的代码它执行运行中才拼出来的代码。更难审查，因为你读到的代码不是全部会运行的代码。
用到 DSH 宿主内部的包它直接用了 DSH 自带的内部包，所以会绑定特定的 DSH 版本。

值得多看一眼的几种

  • 安装时就会运行脚本。包里带了一段脚本，装上的那一刻就会跑，你还没打开插件。建议先读一下，或者安装锁定了 commit 的版本。
  • 直接连接固定 IP 地址，或者用没加密的 http。有时无害（比如一个 schema 网址），有时不是。标签会写出具体地址，方便你判断。
  • 会改动 DSH 自带的组件。插件覆盖或禁用了 DSH 自带的东西。深度集成时是合理的，但它会改变你装它时并不想改变的行为。

最常见的组合「会联网，并用到你的密钥」，任何模型类插件都是这样。它是一条信息，不是警报。

实用习惯

  • 优先选标签和它宣称的功能对得上的插件。一个主题插件却能运行命令，值得问一句为什么。
  • 你依赖的插件，锁定版本或 commit，主动更新，不要自动更新。
  • 点开插件页上的源码链接看一眼。只要一分钟，这是标签替代不了的一步。
