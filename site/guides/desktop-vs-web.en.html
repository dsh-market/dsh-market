Desktop app or dsh web: where your plugins live

DeepSeek Harness runs two ways, and each keeps its own list of plugins. Most "I installed it but it is not there" problems come from looking in the other one.

Two separate lists

dsh web runs on a machine, usually in a terminal, and you open it in a browser. Its plugins live in a profile on that machine, by default called web. The desktop app is an application with its own profile. A plugin installed into one does not appear in the other.

How to install in each

  • dsh web: use the market inside the page, or run dsh plugin --profile web add <name> on the machine that runs dsh.
  • Desktop app: the app installs plugins itself. Use Settings → Plugins, or the market inside the app, which hands the work to the app's own plugin manager.

If dsh web runs on a server

The plugin has to be installed on that server, not on the computer whose browser you are using. The market page you see is served by the server, and it manages the server's profile.

Why the two behave a little differently

  • The desktop app's plugin manager has its own rules. For example it will not remove a plugin that a session is using, and it cannot update the market in place, because that would unload the code doing the update.
  • On dsh web the market runs pnpm itself, so it can retry a refused step. See the release-age wait.

Checking where something went

Open the plugin list in the place you expect it. If it is missing, check the other one, and check that dsh web is the instance you think it is when you run it on more than one machine.
