安装 DSH 插件

先选你在用哪个 dsh，再把插件名粘进来——命令会出现在下面，复制后粘到终端回车。

插件页「安装」一栏里的那串名字。直接粘 GitHub 地址也行，会改成 github:owner/repo。

dsh plugin --profile web add billion-context

在运行 dsh 的那台机器上执行。profile 不叫 web（自己起过名字）的话，把 web 换成你的。

桌面版在应用里装，不从命令行装：

  1. 打开 设置 → 插件
  2. 点 安装，把插件名粘进去

桌面版和网页版的插件各存一份，网页版装了的不会出现在桌面版里。

装完怎么确认

刷新 dsh web 页面，打开 设置 → 插件，列表里有它就是装上了。多数插件刷新页面就生效，少数要重启一次 dsh web。

更新和卸载

更新：把 add 换成 update，再执行一次，就会装到最新版本。想停在某个版本，在名字后面加 @版本号。

dsh plugin --profile web update billion-context

卸载：把 add 换成 remove。

dsh plugin --profile web remove billion-context

桌面版都在 设置 → 插件 里点更新和卸载。

装不上？

下面几种是真实会遇到的情况，对着提示找。

提示版本太新，或「没有匹配的版本」

npm 有安全检查：发布不满约 24 小时的版本默认不允许安装，防止供应链投毒。等过了这段时间再装就好。国内镜像还会比官方源晚一些，所以「没有匹配的版本」通常也是在等同步，不是插件没了。

确实要马上装，可以在命令里加 --config.minimum-release-age=0：dsh plugin --profile web add --config.minimum-release-age=0 插件名。这会跳过这道检查，只对你自己确认过来源的插件用。

提示在等写入锁，或者安装卡住不动

另一个 dsh 或 pnpm 正在改同一个 profile。先关掉所有 dsh（包括桌面版）再试一次。确定没有在跑的话，删掉 profile 目录里的 package.json.lock 再试。

下载卡住、报超时

网络问题。先确认代理本身能用；用代理的话，让终端也走代理再重试。国内网络可以从官方源换到镜像。

装完在设置里找不到

多半是装到了别的地方：桌面版和网页版各存一份；在服务器上跑 dsh web 的话，要在那台机器上装。

装之前请知道

插件是第三方代码，装进来就用你自己的权限运行：能读文件、用你的密钥、连网。来源不确定的插件先看仓库再装；能钉到某个提交更稳（github:owner/repo#sha）。
